Playback recovery center

When a channel works in VLC but not the browser, troubleshoot the manifest, segments, CORS, DRM and supported codecs. The browser's final message does not prove which step failed.

1. Identify the actual failure

Open DevTools (F12) → Network → Preserve log → filter m3u8, mpd, ts, m4s. Click Play, then inspect the first failed manifest or segment.

401 / 403

Check subscription, host authorization and geographic rules. Contact the broadcaster if you don't administer the media host.

CORS warning

Your owned origin must include the requesting site in Access-Control-Allow-Origin for every media response.

404 / 410

Expired playlist, missing segments or incorrect path. Check origin logs and manifest references.

DRM / Widevine

Use the licensed DRM player and EME integration. VLC is not a replacement for a DRM license.

Codec / MediaError

Inspect video/audio codecs. Test a compatible H.264/AAC rendition or the official app.

Buffering / timeout

Inspect segment durations, 200/206 responses, bitrate, live latency and origin stability.

2. Check an authorized source

Replace the placeholder below with a media server you own or administer; never publish signed URLs or session tokens.

curl -sSIL "https://media.example.net/live/demo/index.m3u8"
ffprobe -v warning -show_streams -of json \
  "https://media.example.net/live/demo/index.m3u8"

For a dedicated media app, choose VLC → Media → Open Network Stream. Adjust Input/Codecs → Network caching to test buffering.

3. Use approved paths

Use the broadcaster's official website/app for protected streams. If you control the media server, correct CORS and SSL at the source; serve all playlists, segments and keys through HTTPS. A restricted owned-origin proxy can be used for internal deployments only.
